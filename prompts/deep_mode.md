# Prompt Module — Deep Mode

## When invoked
- Selected for high-risk, high-freshness, high-visibility, or contested tasks.
- Triggered by intake recommendation, evaluator failure, or explicit user requirement.
- Requires full claim-level workflow and policy-conformant evidence routing.

## Inputs
- **Required**
  - `task_profile` indicating elevated assurance needs.
  - Comprehensive `source_plan` including authoritative classes.
  - Full module chain artifacts (retrieval, claims, conflicts, uncertainty).
- **Optional**
  - External review rubric or stakeholder acceptance criteria.
  - Prior failed drafts for targeted remediation.

## Procedure
1. Execute full source routing with redundancy across classes.
2. Perform structured extraction, claim atomization, and evidence binding.
3. Resolve conflicts explicitly and document residual uncertainty.
4. Assemble and compose with section-level claim traceability.
5. Run full evaluator and critic passes with revision loops as needed.
6. Finalize only when blocking issues are cleared or explicitly deferred.

## Outputs
- `deep_execution_record` spanning all module artifacts.
- `high_assurance_claim_inventory` with full traceability.
- `review_ready_response` plus unresolved-risk disclosures.

## Quality checks
- Every major conclusion is traceable to citation-backed claims.
- Conflicts and uncertainties are explicitly handled, not suppressed.
- Evaluator and critic blocking issues are resolved or disclosed.
- Final output meets high-assurance acceptance criteria.

## Failure patterns
- **Symptom:** Deep workflow produces volume but not clarity.
  - Cause: No synthesis checkpoints.
  - Fix: Add periodic decision summaries between stages.
- **Symptom:** Revision loops never converge.
  - Cause: No explicit closure criteria.
  - Fix: Define blocking issue thresholds and exit conditions.
- **Symptom:** High assurance claimed with weak provenance.
  - Cause: Traceability links incomplete.
  - Fix: Enforce claim-to-source trace audit before finalization.
